# Research dashboard and decision replay

This skill governs only `nse/research/dashboard.py` and `nse/research/decision_replay.py`, and the static pages they generate. `platform/web` is a separate React client. Chart, scanner, plan and journal work in `platform/web` is not governed by this skill. Vendored design skills advise on that client. They do not extend this skill's scope.

Static HTML, inline SVG and a little vanilla JavaScript generated by Python. No frontend
stack, no CDN, no external fonts or scripts: pages from these two modules open offline from `file://`.

## Run

```
python3 -m nse.research.cli scan --as-of <date> ... --out nse/output/scan
python3 -m nse.research.cli replay-decision --symbol <S> --as-of <date> ... --out nse/output/replay-<S>
python3 -m nse.research.cli dashboard --scan-dir nse/output/scan --out nse/output/dash [--bundles-dir ...]
python3 -m nse.validation.run_all --group dashboard
```

## What a page must show (and never hide)

- Every symbol, including REJECTED, BLOCKED, DATA_INSUFFICIENT and MANUAL_REVIEW results,
  with the deciding gates and reasons.
- The banner: research decision support; no status approves a trade; not externally
  validated. Readiness states shown separately, never one green tick.
- Charts with candles up to the as-of only. Tested, invalidated and unknown-freshness
  zones are drawn with their own style and legend, never in the fresh style.

## Hard restrictions

- The dashboard reads reports and decision bundles; it computes no gate, score or status.
- Decision bundles are prefix-invariant: adding later candles never changes a bundle at T.
- All text is HTML-escaped. Output is deterministic (no clock).

## Verification

`tests/test_research_dashboard.py` passes (prefix invariance, status styling, counts
reconcile with summary.json, escaping, no external URLs, determinism). Open the generated
`index.html` and one stock page and compare a candidate's gates with `candidates.csv`.
